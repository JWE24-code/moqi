# 0.5.1 — Sonar to zero, and installs on dsh 0.2.1

Two goals, split into tasks that agents can run in parallel. Every task has its
own branch and owns a set of files that no other task touches, so the PRs
merge in any order without conflicts.

1. **Sonar to zero** across all four projects: `moqi`, `dsh-jev-loop`,
   `dsh-pii-anonymizer`, `moqi-jev-loop`.
2. **Installs on the newest dsh core** (`@deepseek-ai/dsh@0.2.1-rc.2`, the
   `latest` dist-tag since 2026-10-17) work for moqi and the three plugins.

### dsh 0.2.1-rc.2 installs

I reproduced each path on Linux, using a throwaway npm prefix and `DSH_HOME`:

- `npm i -g @deepseek-ai/dsh@0.2.1-rc.2` works. npm 11 skips five install
  scripts (`dsh-subprocess-local`, `koffi`, `node-pty`, …). On Linux this does
  no harm: the prebuilds ship ready and the skipped postinstall only fixes the
  macOS `spawn-helper` bit.
- `dsh plugin --profile X add <pkg>` works for all four packages, separately
  and together. dsh 0.2.1 now writes `autoInstallPeers: false` itself, so no
  `@deepseek-ai/*` copies land in the profile. The plugins print
  `Issues with peer dependencies found` because their `@deepseek-ai/*` peers
  are not optional. That message is noise, but it is the kind that gets
  reported as "install broken".
- `npm i -g moqi-tui && moqi` works. `install-profile` links 305 harness
  packages, and the TUI boots with nothing on stderr. A profile with moqi and
  all three plugins also boots.

**Linux CLI is fine. The breakage is off Linux.** Reading the installer finds
three hard failures on Windows, and the 0.2.1 release pushes people towards
the Windows desktop app (most upstream 0.2.1-rc.2 discussions are Windows
desktop):

1. `scripts/harness-root.mjs:36` and `scripts/link-harness-types.mjs:27` find
   `dsh` with `/bin/sh -c 'command -v dsh'`. That path doesn't exist on
   Windows, so `findDshRoot()` returns `undefined`, no harness packages get
   linked, and the app cannot boot. The comment in `install-profile.mjs`
   itself says the links are "what makes a freshly installed app boot at
   all".
2. `scripts/harness-root.mjs:81` calls `symlinkSync(…, 'dir')`. On Windows
   that needs Developer Mode or an elevated shell; a `'junction'` does not.
3. `bin/moqi.mjs` runs `execFileSync('dsh', …)` without a shell. On Windows,
   npm installs `dsh.cmd`, and Node refuses to spawn a `.cmd` file without
   `shell: true` (EINVAL since Node 18.20.2/20.12.2).
4. `scripts/install-profile.mjs:170` (`hasCommand`) has the same `/bin/sh`
   problem. There it only demotes pnpm to npm.

There is also a related upstream failure mode (deepseek-harness discussions
#10364 and #10338): a plugin that lists `@deepseek-ai/*` under `dependencies`
puts an old core copy in the profile. That copy shadows the in-box one, and
startup dies with `required plugin did not activate … tools`, or later with
`reading 'prepare'`. **None of our four packages does this today.** The
second task below adds a CI guard so it stays that way.

> **Open input:** I don't know where the install reports came from (who,

> and the desktop app, because that's what the code and the upstream

## Rules for every agent

- Work in a git worktree off `origin/main` (on the plugin repos too), on the
  branch named in the task. One PR per task. Open it as a **draft** and never
  merge it yourself.
- Read `AGENTS.md` first. Run `npm ci`, then `node scripts/link-harness-types.mjs`
  (needs a `dsh` on PATH), then `npm run typecheck`, `npm test` and
  `npm run test:pty`. All of them must pass before you push.
- **`lib/` is committed.** Every `src/` change goes in with its rebuilt `lib/`
  (`npm run build`).
- Touch only the files your task owns. If a fix needs a change in another
  task's file, note it in the PR body instead of making it.
- Change **behavior: none.** These are refactors. Before refactoring, add a
  test that pins the current behavior of any function whose complexity you
  split.
- Precedent for every rule here is in `docs/sonar-issue-resolution.md` and in
  commits `acd2872` (S3776), `868e0b1` (S8786 and the mechanical classes) and
  `4c07a9f` (S5443 in tests: no `/tmp` writes). Fix things the same way.
- **Fix, don't suppress.** A `// NOSONAR` or "won't fix" is allowed only for a
  finding that is false *after* you have read the rule. Put the reason in the
  PR body under "Sonar: accepted". The user marks those in SonarCloud, because
  agents have no Sonar token.
- **Done** means the SonarCloud PR analysis on the draft PR shows **0 new and
  0 remaining issues in the owned files**. Check with
  `api/issues/search?componentKeys=<key>&pullRequest=<n>&resolved=false`.
- Never boot moqi against the real `~/.dsh`. A quit rewrites the shared
  `tui-state.json`. Use a throwaway `DSH_HOME` (and `--dump-config` where
  that's enough).

## Track C — installs on dsh 0.2.1 (3 tasks)

### `install-win`: moqi on Windows (CLI) — the likely root cause

Branch `fix/windows-install`. Owns `scripts/harness-root.mjs`,
`scripts/link-harness-types.mjs`, `scripts/install-profile.mjs`,
`bin/moqi.mjs` and `.github/workflows/ci.yml`.

1. Write one cross-platform `which(name)` in `scripts/harness-root.mjs`: walk
   `PATH` and, on Windows, `PATHEXT`. Use it in all three places that call
   `/bin/sh -c command -v`, and drop `/bin/sh`.
2. On Windows, npm's `dsh` shim is `dsh.cmd` in the npm prefix. Find the
   package root from `<prefix>/node_modules/@deepseek-ai/dsh`; don't walk up
   from the shim's realpath.
3. `linkHarnessPackages`: use `symlinkSync(src, to, process.platform ===
   'win32' ? 'junction' : 'dir')`.
4. `bin/moqi.mjs`: spawn `dsh` so that `.cmd` works. Either use the
   `which()` result with `shell: true` on win32 (quote the arguments), or run
   `node <dsh-root>/<bin entry>` directly, which avoids the shell entirely and
   is preferred.
5. CI: add a `windows-latest` job, `install-smoke`, that runs
   `npm i -g @deepseek-ai/dsh@latest`, `npm i -g <packed moqi tarball>`,
   `moqi install`, then `dsh --profile tui --dump-config` and `moqi --help`,
   with a fresh `DSH_HOME`. Run the same job on `ubuntu-latest` and
   `macos-latest`.

Done when the `install-smoke` job is green on all three OSes in the draft PR.

### `install-peers`: plugin manifests and a dependency guard

Branch `fix/optional-peers` in each plugin repo, plus
`scripts/check-harness-deps.mjs` in moqi.

1. `dsh-jev-loop`, `dsh-pii-anonymizer` and `moqi-jev-loop`: mark every
   `@deepseek-ai/*` peer optional in `peerDependenciesMeta`, the way
   `moqi-tui` does. That removes the "Issues with peer dependencies" warning
   that `dsh plugin add` prints. Keep the version ranges on `dsh-jev-loop`;
   they still match `0.2.1-rc.2`.
2. Add a CI check to each of the four repos that fails if any `@deepseek-ai/*`
   name appears in `dependencies`, which is the upstream #10364 failure shape.
   In moqi this goes in a new script; in the plugins it's a short inline step.
3. Add a CI job that installs dsh at `@latest` and at `@next`, runs
   `dsh plugin --profile t add <this package>` in a fresh `DSH_HOME`, and
   asserts that `dsh --profile t --dump-config` exits 0 and that
   `<profile>/node_modules/@deepseek-ai` is empty.
4. Bump the patch versions: `dsh-jev-loop` 0.1.4, `dsh-pii-anonymizer` 0.2.1,
   `moqi-jev-loop` 0.1.4. Add `CHANGELOG.md` lines. Don't publish; releases
   are the user's step (`docs/releasing.md`).

### `install-docs`: desktop app and upgrade notes

Branch `docs/install-021`. Owns `docs/install.md` and the README's Install
section.

- **Desktop app (0.2.1, Electron).** dsh lives inside `app.asar`, there is no
  `dsh` on PATH, and there is no terminal. Moqi needs the CLI. Say so plainly
  and give the one-liner to add it. The three plugins *can* be installed into
  the desktop profile. Document that, and the #10364 check: if the desktop
  won't start after a plugin install, look for `<profile>/node_modules/@deepseek-ai/*`.
- **Upgrading an older profile.** Profiles made before 0.2.1 may lack
  `autoInstallPeers: false`, and may hold stale `@deepseek-ai/*` copies in
  `node_modules`. The fix is `moqi install` (it rewrites the workspace file
  only if missing; check that) followed by deleting the stale copies.
- **Version managers (mise/nvm).** The 305 harness links are absolute paths
  into the dsh install. Changing the Node version leaves them dangling; re-run
  `moqi install`.
- **npm 11 "install scripts skipped" warning:** harmless on Linux and macOS
  (see above). Say so, so people stop reporting it.

Don't document the Windows fixes until `install-win` has merged.
